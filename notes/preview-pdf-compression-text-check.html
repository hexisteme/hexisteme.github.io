Compress a PDF on Mac with Preview: Check the Small Print Before You Send

← hexisteme · notes · 2026-09-10

English · 한국어
Preview made the sample smaller, while fine print on the image-only page softened. Save a new copy and compare the details that matter before sending it.

If you need to email a PDF from a Mac, Preview offers a built-in way to make it smaller: File > Export > Quartz Filter > Reduce File Size. Apple also warns that compression can lower quality, but that warning leaves an important practical question: does a smaller PDF still keep the information you need to read?

The test used a small synthetic document. It is not a customer file, a scanned record, or an upload. The two-page PDF contains the same sheet twice:

  • Page 1 has selectable vector text, including English, Korean, small 6 pt lines, and synthetic IDs.
  • Page 2 is a 300 dpi grayscale image-only copy of the page, with a small amount of seeded paper-like variation and no embedded OCR text.

That distinction matters. A PDF can look like a document while its page is really an image.

Check your own PDF before you send it

Before choosing a compressed copy, make a new file and inspect it:

  1. Open the PDF in Preview and choose File > Export.
  2. In the export dialog, enter a new filename; do not overwrite the source while testing.
  3. Choose Quartz Filter > Reduce File Size if a smaller attachment is the priority.
  4. Click Save to create that separate exported copy.
  5. Open the new PDF beside the original and compare the same page at the same zoom.

The English menu words are Apple’s documentation wording. This test does not claim that an English-language Preview interface was run.

The controlled exports were run in macOS 26.6.2 with Preview 11.0; the source file stayed unchanged. The test compared three exports of the same two-page source:

  1. A control export with no Quartz filter and no extra export options.
  2. Reduce File Size as the Quartz filter, with the other options off.
  3. No Quartz filter, with Optimize images for screen and Save images as JPEG selected. PDF/A, linearization, and embedded text were off.

What changed in this test

The Reduce File Size export made this particular file much smaller. It also reduced the image-only page from 2550 × 3300 to 1224 × 1584 pixels.

In the comparison crop, the page with vector text kept its fine strokes. On the image-only page, the 6 pt Korean line looks softer after reduction, but it is not accurate to say that all text became unreadable. That is why a byte count alone is a poor decision rule.

The other two checked export options did not make this fixture smaller. That does not mean those options never help other PDFs. It only records their result for this source, these settings, and this Preview version.

In this run, Preview’s accessibility output recognized some words on the image-only page even though the PDF had no embedded text there. That observation does not establish vector text or stored OCR. Manual clipboard copying was not tested; the measurements and the small-print view are separate checks.

What to inspect in the exported copy

Look at small print, IDs, totals, dates, tables, and any image-only scan page. Select or copy text only as an additional check. If a reader needs every small character, keep the original or choose the version that meets that reading requirement. Do not expect repeated compression of a blurry result to restore detail.

The built-in command is useful because it is already on a Mac. It is not a promise that every PDF will shrink, stay equally sharp, or preserve every workflow requirement.

How this test is limited

This was one synthetic two-page document. It does not cover passwords, forms, signatures, hyperlinks, color scans, OCR, complex fonts, or a real person’s paperwork. It does not measure upload acceptance, legal validity, or accessibility. Apple’s own Preview guide says compressed output may be lower quality and that file size and image quality can vary with the options you choose.

Use the test as a way to decide what to inspect, not as a universal compression recommendation. If the page contains a number or sentence that must be read correctly, verify it in the exported copy before sending it.

Disclosure: AI generated the synthetic document, ran local structural measurements, operated the Preview UI export, and reviewed the result. No additional PDF-compressor was purchased; files stayed on this Mac. No customer document was used or uploaded.

FAQ

Will Reduce File Size always keep my PDF readable?

No. Apple says compressed output can be lower quality. This test found softer small text on its image-only page, so check your own important pages before sending.

Does selectable text prove that a PDF page is vector text?

No. Text selection is only an additional check. This experiment used an image-only page with no embedded OCR text and keeps page structure separate from selection behavior.

Can I restore a blurry compressed PDF by compressing it again?

Do not rely on that. Keep the original and choose the copy that meets the reading requirement after comparing the same page at the same zoom.
